# ARCHITECTURE.md — Katalyst

> The technical counterpart to `PRODUCT_REQUIREMENTS.md`. That document says what the tool must do and why; this one says how the system is shaped, where each rule is enforced, and how it runs. It describes the system **as built and as planned**, and each section says which.

**Living document.** Last verified: 2026-09-21. Any pull request that changes a boundary, a layer, a data flow, or a runtime dependency updates this file in the same PR. A stale architecture doc is worse than none: it is the "not knowing why it did that" failure in written form.

**Status markers.** `[planned]` — decided, not yet in the repo. `[built]` — in the repo and covered by the tests named. `[stretch]` — designed for, not scheduled.

## 1. The system in one picture `[built]`

Both halves of the drawing below run today, and so does the line between them: **the model pipeline, the event stream and the browser that draws it are built**. What is still drawn ahead is the stored state and the screens the trade needs, and both are named again under it.

```
 ┌──────────────────────────── browser ─────────────────────────────┐
 │  React + TypeScript (Vite)                                       │
 │  workbench canvas · inspector · diff overlay · delta rail ·      │
 │  branch panel · keyboard and outline                             │
 │  [planned] world-state strip · time axis · thesis dock           │
 └───────────────▲───────────────────────────────▲──────────────────┘
        HTTP JSON │                               │ server-sent events
                  │                               │ (one-way stream: proposals,
                  ▼                               │  rejections, propagation)
 ┌──────────────────────────── backend ─────────────────────────────┐
 │  FastAPI (Python web framework)                                  │
 │                                                                  │
 │  api/        routes, request/response shapes, the event stream   │
 │  engine/     talks to the model; turns answers into proposals    │
 │  domain/     PURE: graph rules, propagation, branches. No I/O.   │
 │  grounding/  outside prices: a saved file first, a venue second  │
 │  thesis/     the trade: an edge, a position, a card, a document  │
 │  settings.py the only place environment variables are read       │
 │                                                                  │
 │  storage: [planned] none. A finished generation is served back   │
 │           by its id from the line-by-line file the run already   │

 └──────┬──────────────────────┬────────────────────────┬───────────┘
        ▼                      ▼                        ▼
   Anthropic API         Polymarket Gamma API        FRED API
   (claude-sonnet-5,     (prediction-market          (economic series,
    web search tool)      prices, no key)             free key)
```

**What runs.** The browser app and the Python server both start, and `api/` answers eleven routes for real: whether the server is up and what it can do without a key, what the product calls itself, the stored worked example, what a branch does to a map (`POST /api/worlds`, `POST /api/worlds/diff`, `POST /api/worlds/conditional`), and — new with stack 04 — **a map written from a sentence**: `POST /api/generate` as a stream, `POST /api/generate/insert` for one drafted claim, and `GET /api/generate/{generation_id}/transcript` for the working. **The generate request names how the run starts** — `start`, either `live` or `replay` — and the route does what it was asked or says plainly why it cannot; it never reads the key to choose, and never substitutes one for the other. A request that names nothing plays a recording, because a request that did not ask to spend money must never spend it. `domain/` holds the rules and the arithmetic and nothing else: it folds a branch onto a map, works the likelihoods through, and says what moved. **The canvas asks the three world routes**, so every number on screen is the engine's.

**The browser half is built as far as the map goes.** It draws the stored example from `GET /api/fixtures/hormuz` — tiles with typed sockets, wires carrying the shape, strength and provenance of each push, automatic left-to-right layout on a background thread — and beside the map a panel that answers "why is this number what it is". Two worlds lie over each other: the union of the base map and a branch is laid out once and painted twice in the same coordinates, with one word per claim saying what the edit did to it, a rail listing the endings the edit can reach, and a panel listing the branch's edits in the order they were made. The whole of it works from the keyboard — along the wires rather than across the glass — and the same world exists as a nested list for a reader who never sees the picture. **No number on any of those screens was computed in the browser.** The canvas asks the server for a world, a difference and the number on one arrow, and draws what comes back; a test walks the syntax tree of every file that draws one of the map's numbers and fails on any multiplication of one. When the server cannot answer, the page falls back to the stored example and says on screen that it has, because a map you can still read beats a blank one.

`[planned]` **Inside the browser box, three things are drawn because they are decided rather than because they are written**: the world-state strip of tradeable instruments, time as a real axis on which lags are real distances, and the thesis dock. All three are stack 05's or later.

**The event stream is real, and so is the browser's half of it.** `POST /api/generate` writes `event:` and `data:` lines as a generation happens — a claim proposed, a claim refused, the likelihoods worked through, the verdict, the receipt, and why it stopped — and a terminal with `curl -N` can watch a map being built. **The browser reads the same stream and draws the map as it arrives**: a reserved rectangle where the next claim will go, claims as they are accepted, wires in causal order, every refusal beside the map in the validator's own words, and the likelihood chips filling in once at the end. There is no spinner anywhere in the product, and a test walks every component and every stylesheet to keep it that way.

**`grounding/` and `thesis/` have code now, from a venue's price to the thesis a reader carries away** `[built]`. `grounding/` reads a prediction market's own answers back from a committed dated file under `backend/recordings/quotes/` and works a price out of them — the best bid, the best offer, the instant the book was true, the identifiers, and the venue's four flags saying whether it still trades. Asking Polymarket again is one function that nothing calls unless a reader asks for it, so no test and no build ever leaves the machine. **Recorded first, fetched second, and a venue's number a point rather than a range** are decision record 0020's rules, and that is what shipped. `thesis/` holds the arithmetic on top, in eight files. An **edge** is a claim's model number, read from the world with nothing supposed in it, set against the price somebody would actually deal at — the offer to buy, the bid to sell, less the venue's fee — or, where the two cannot honestly be compared, a named refusal and the break-even price instead (decision record 0018). `draws.py` names **the one thing this layer asks of the engine**: for each drawn world, the day each claim came on, the day it went off, and how much that world counts. On that sample, `paths.py` walks a daily price path applying only what the market has not already priced, `position.py` holds the stop, the target and the horizon the reader typed and answers how often each is reached first, `lift.py` ranks the claims that kept company with being stopped out, and `ceiling.py` works out the greyed quartered-Kelly ceiling labelled *never size to this*. `card.py` arranges all of it into the thesis a reader carries away and computes nothing another file owns; `export.py` writes that out as a document a program can read and a page a person can read, with the description of the document generated from the shapes and committed beside them.

`[planned]` What is still ahead in both packages: the economic-data adapter that anchors a price ending — a measured level is an **observation** and never fills the `market` belief — the adapter that turns the engine's own sample of worlds into `Draws`, the sweep that fills *what to watch* (its two filters are not built, and a card is handed those rows today), the five routes that serve a card, and the dock that draws one. **Kalshi is cut from version one.** The web search that does run today lives inside `engine/` as part of a model call rather than in `grounding/`. And there is still no storage — no database file, no volume declared in either compose file, nothing kept between requests except what one running process holds in memory for the life of that process. **And no database is planned**: a finished generation will be served back by its id from the line-by-line file a kept run already writes, which is the same format a recording uses (decision record 0021).

Two halves, one contract: the backend publishes an OpenAPI description (a machine-readable list of every route and data shape); the frontend's TypeScript types are generated from it and committed, and continuous integration fails if regeneration would change them. The two halves cannot drift silently.

## 2. The one rule that shapes everything `[built]`

Both halves are mechanical today. The boundary that keeps the rules layer pure is checked on every pull request; `validate` refuses a bad map; and **the recorded model answer carrying a loop is committed and replayed on every run of the build** — `test_expand_rejects_cycle`, against a cassette in `backend/tests/cassettes/`.

**The model proposes; the domain layer disposes.**

The language model never edits the graph. It returns *proposals* — one proposition or one link per call — and code the team wrote checks each proposal against the rules of the graph. A proposal is accepted (and gets a server-minted identifier) or rejected with a reason. Both outcomes are events on the stream, so the user sees the model's misses as well as its hits.

This is why `domain/` is pure: no network, no model, no clock, no randomness except an explicit seed. It is the part of the system whose correctness is *proven by tests* rather than *requested of a model*, and it is the part a reviewer should read first.

Enforced by `test_domain_imports_nothing_impure`, in `backend/tests/unit/test_import_boundary.py`: it reads every file under `domain/` and fails if one of them imports `engine/`, `api/`, `grounding/`, or a model client. It runs in the `backend` check on every pull request, and two further tests in the same file check the checker itself, so a boundary test that has quietly stopped looking cannot pass by accident. The same checker is pointed the other way by `test_the_rules_layer_never_reads_the_examples`, so whether a map is valid can never come to depend on which worked examples we ship.

**The two price layers are held to the same shape** `[built]`. `test_grounding_imports_nothing_above_it` and `test_thesis_imports_nothing_that_serves_or_fetches` say that `grounding/` may read the rules layer and nothing above it, and that `thesis/` may read worlds and prices and ask nobody for them — so the trade's arithmetic cannot quietly acquire a network call. A third test, `test_the_price_layer_may_not_reach_for_another_network_library`, names the libraries that open a connection, because a checker that listed only the one library in use today would pass a layer that had switched to a different one. One function in the whole program opens a connection to a venue, it is named for what it does, and nothing calls it unless a reader asked.

The disposing half exists too: `validate` in `domain/validity.py` walks a whole map and returns every fault at once, each named in the claim's own words rather than by identifier.

**A proposal is judged against the map it would leave behind, and judged twice.** `engine/expand.py` builds the candidate map, runs `validate` over the map as it was *and* over the map the proposal would make, and keeps only what is **newly** wrong. A map that was already imperfect therefore cannot make an innocent proposal guilty, and a proposal that breaks a rule cannot hide behind a map that already broke it. The one claim a person types themselves, through `POST /api/generate/insert`, is judged by that same code before it is handed back.

**After a refusal the same question is asked again, up to three times, and no attempt is ever told what was wrong with the last** (decision record 0003, amended 2026-09-17). Violation text never enters a prompt, so a prompt can never steer the model toward passing the validator rather than being right. Three refusals in a row close that line of the map, and every refusal is an event on the stream with the validator's own sentence.

## 3. The flow of a generation `[built]`

**All eight steps run, end to end, and the browser watches them.** A sentence goes in at the top, a map comes out at the bottom, and every step in between is code in this repository.

```
 1  user types a hypothesis (+ optional target, + optional own likelihood)      [built]
 2  api/ opens an event stream to the browser                                   [built]
 3  engine/ asks the model for ONE proposal at a time                           [built]
       ├─ system prompt is stable and cached (cheaper repeated calls)
       ├─ the model may call the vendor's web-search tool for evidence
       └─ the answer is a pydantic object (schema-guaranteed JSON)
 4  domain/ validates the proposal → accept (mint id) | reject (reason)         [built]
 5  api/ emits the event; the canvas draws the claim or the refusal at once     [built]
 6  repeat 3–5 until the map reaches a tradeable ending or a stop rule          [built]
 7  domain/ propagates beliefs (seeded); one event carries the whole world      [built]
 8  the generation receipt (model, tokens, cache reads, searches, dollars)      [built]
```

**Eight events, and one line that is never recorded.** Everything a client ever sees is one of these, written by `engine/events.py` as `event:` and `data:` lines: `generation_started` (which carries the seed the server minted, so the run reproduces from its first moment), `proposal_accepted`, `proposal_rejected`, `beliefs_propagated`, `verdict` (the Verify door only), `receipt`, `done`, `failed`. What a client should do with a name it does not know — ignore it, and say so rather than fail — is the stream chapter's rule in `spec/generation/streaming.md`. Two things deliberately make no event at all — the model saying a line is finished, and a claim's third refusal closing it — because the next event's frontier already says what happened.

**Each of those eight is a decision, and a recording is exactly those, line for line.** A ninth kind of line, `activity`, is not one: it says what a model call is doing *this second* — the search it just ran, one thing that came back, the sentence it is thinking — and it is sent on a live run only and **never written to a recording, a transcript or a kept run, never replayed, never invented by a replay, never billed and never counted by the transcript counter** *(2026-09-22, decision record 0027, Kent's R44 and R47)*. The name is deliberately absent from the tables `engine/events.py` writes and reads a recording through, so a recording cannot hold one; a file that does is refused by name. This is why record 0012 — *a replay is the real stream played back* — is untouched by it: a replay shows no activity for the same reason it shows no seconds, which is that the thing being reported does not exist in a replay.

**What it costs the rest of the system: nothing.** The live call is the only one that is streamed and the only one that asks the model to summarise its thinking; the recorder and the recorded exchanges under `backend/tests/cassettes/` send the request they always have, byte for byte, and the prompt's fingerprint — the standing text plus the shapes of the answers, and nothing else — does not move. A live request differing from the recorder's is decision R34's precedent, already in force for effort.

**Step 3 in full.** `engine/expand.py` asks for **one** proposal: a claim plus the one arrow into it, an arrow between two claims already on the map, or a typed `Stop`. Three things the shape it fills makes impossible, because the fields are simply not there: minting an identifier, declaring its own provenance, and returning more than one thing. Identifiers are minted by `engine/ids.py`; **provenance is written by us in `engine/grounding.py` from what the search tool actually returned in that call** (`documented` when a cited page is one the tool returned, `argued` when there is a mechanism but nothing kept, `asserted` when there is neither — and since every arrow must carry a rationale, no arrow this pipeline accepts is ever `asserted`); an address the model typed that the search never returned is dropped, with a note in the transcript.

**Step 6's stop rules.** A generation ends for exactly one of seven reasons, and `done` names it: `reached_terminal`, `claim_cap`, `depth_cap`, `width_cap`, `refusal_cap`, `spend_cap`, or `no_terminal`. The caps are arguments with defaults — five layers deep, three children a claim, thirty claims, three refusals in a row on one claim, three lines worked at once, a whole-run search budget, and **a $15 hard stop checked after every call**. Running out of search budget is never a reason to stop: later arrows simply come back `argued`, and the origin marks on the canvas show where the evidence thins out.

**Step 7 is one event, at the end.** `propagate` in `domain/propagation.py` turns a map and the values its edits fixed into a world: a likelihood and a range for every claim on the day it is judged, a likelihood for every day of the window, and a named word beside each of those days. It is seeded — the same map, branch and seed give a byte-identical world on any machine.

**Two arithmetics stand behind `propagate`, and one word says which runs.** `today` is the pair of nested loops the engine has run since stack 03a: two thousand versions of the map, eight worlds of dice under each (decision record 0014). `by_deadline` is decision record 0016's core, in which a claim's number becomes *the chance it happens by its deadline* — one forward pass works out **when** each claim happens, an exact solve answers **whether**, and where something was reported to have happened a weighted sample of fifty thousand worlds corrects the answer for the timing the news moved. Its arithmetic lives in five new pure modules under `domain/`, importing in one direction only: `rates.py` (stated chances into rates) ← `states.py` (a claim that can stop, and its two times) ← `forward.py` (one pass, causes before effects) ← `solving.py` (whether, exactly) ← `sampling.py` (the drawn worlds, and the event days stack 06 reads).

**Which one runs is `DEFAULT_ENGINE` in `domain/propagation.py`, and it is `propagate`'s own default** — the one place every caller already reads, so no route can be left behind when it changes. It is a constant and never a setting read out of the environment: a screen whose numbers depend on how a machine was started is state nobody can trace to an input, a rule or a source. `test_the_flip_is_one_word_in_one_place` parses every file the server ships and fails if an engine's name is written down anywhere else. **It still says `today`**, so every number on every screen is the old arithmetic's; the new core is built, checked against two independent enumerators, and behind the flag. The flip is its own pull request.

**Each version draws every arrow's push from a spread read off where that arrow came from** — narrow for an arrow citing a page the search returned, widest for a bare assertion — so "how well-backed is this" becomes "how wide is this" with nobody asked a second question. The width is derived from that one word every time it is needed and is never stored: there is no `strength_lo` and no `strength_hi`. `domain/diff.py` then compares two worlds. The likelihoods arrive **once**, when the map is finished, because a number that changes four times as its causes arrive is four numbers nobody computed.

`[planned]` **Step 7 is being rebuilt, and the paragraph above describes what is there today** (decision record 0016, stack 05). What replaces it: a claim's number becomes *the chance it happens by its deadline*; **whether** each claim happens is solved exactly rather than sampled; **when** it happens comes from one forward pass over the window; the two thousand versions of the map ride as one array axis instead of an outer loop, and the eight worlds under each go, with the noise correction and the version weights. Worlds are still drawn, but **from** the answer rather than to make it, because stack 06 needs the day each claim came on and went off. This section is marked `[built]` for the new engine only once the default has changed — the step decision record 0016 calls *the flip*, where every number on the worked example moves at once and the diff of `docs/worked-numbers.txt` is the whole reviewable statement of what moved.

**What the screen says while step 3 takes a minute** `[built]` *(2026-09-21, decision record 0023)*. A model call takes about 52 seconds at `medium` effort and about 110 at the effort the recordings were made at, so between two events a live run is a still picture for a minute at a time. **One strip at the foot of both map screens** says what is happening: the state as a single word, then the run's own sentence — the same element the polite live region is, so the printed and the spoken account cannot drift — then, only while the screen is waiting on the server, how long it has been since anything arrived. The sentence names what is still open, read off the `frontier` both growth events already carry; it counts **proposals**, because the browser cannot know how many calls are in flight and must not guess. **No server change, no ninth event, and nothing spins**: the only thing that changes between two events is a measurement, and `frontend/src/stream/__tests__/noSpinner.test.ts` now walks every timer in the browser code against a named list to keep it that way. A **replay shows no seconds** — it is paced by us, so the reading would be measuring our own pacing. Where the map is coming from — the route, the run's name, the seed — is a *Run details* section of the panel (`components/Inspector.tsx`), not a strip of prose under an empty map.

**When a tile may move** `[built]` *(2026-09-22, decision record 0024)*. A map that builds itself pinned every tile it had drawn, to the pixel, and the pins were never dropped — so a claim drawn before anything pointed at it stayed in the column it landed in, and the arrows that arrived later were drawn doubling back into it. On the **Verify** door that is acute, because the destination claim arrives second with nothing pointing at it at all: on one kept live run, three of nine arrows were drawn pointing backwards. The promise *a placed tile never moves* is now **a tile moves only when an arrow would otherwise point backwards, and once when the run stops.** The pin holds a tile's **row**; its **column** is re-read from the arrows on every pass (`graph/elkGraph.ts`); and the one flag the canvas is already asked to re-frame on is handed to the layout as well, so the map settles — every pin dropped, the whole map laid out as one thing — at the same moment the view re-frames, and the two cannot come apart. **It is a cut, not an animation**: no fourth thing moves and the motion budget is untouched. What it costs, folded event by event through the app's own layering, layout engine and reading-back: while the map grows, **2 tile-moves on 2 arrivals** on the live Verify run and **3 on 2** on the committed recording; at the settle, 4 tiles and 18. The evidence is a fixture — the `events` array of one kept live run, `frontend/src/graph/__tests__/fixtures/` — because the one stream this repository already held is an Explore run on which the defect cannot happen.

**What is beside the map, and what may change it** `[built]` *(2026-09-22)*. The panel beside both map screens was one column holding everything at once, so a click on a tile filled the bottom of a box that did not scroll and looked like a click that did nothing. It is **a few panels with their names at the head of it**, outside the part that scrolls: *This claim* / *This arrow* · *The run* · *Outline* on a map building itself, and *This claim* / *This arrow* · *Branches and changes* · *Outline* on a stored map — a panel a screen does not have is never offered. **Choosing a claim or an arrow is the only thing that changes which panel is on the glass**; an arrival adds a count to a panel's name (*refused 3*, read off the run) and moves nobody. `N` steps to the next panel from anywhere on the screen, the names are a row of labels the arrow keys walk, and every label is a word. `components/PanelSwitch.tsx` draws the names; each screen owns which one is showing, because only the screen knows what a selection means. The panel's width and the map's stage do not change when the panel does.

**A round's answers reach the reader one at a time** `[built]` *(2026-09-22, Kent's answer to the same round of feedback)*. Three lines are asked about at once and their calls finish minutes apart: measured on a live run Kent kept, one round's calls took 131, 44 and 65 seconds, and all three claims reached the screen at 131 — the walk waited for the whole round before folding any of it. `engine/grow.py` now folds each answer, and sends its event, the moment that call comes back. The rule this re-cut is Kent's of 2026-09-21, *a paid call never falls off the receipt*, and it is kept the other way round: **each call is billed the moment it returns, before it is folded**, and whatever a round still has in flight when a fold throws or the reader walks away is waited for, billed and folded into the transcript where nobody will see it. What it costs is that the order of a run's events — and therefore which claims the next round asks about — depends on which call came back first; nothing that has to be exact rests on it, and a replay plays a recording back line for line either way. Held by `backend/tests/unit/engine/test_a_round_hands_answers_over.py`.

**And what the model itself is doing while it waits** `[built]` *(2026-09-22, decision record 0027)*. Measured over the five kept runs under `backend/.runs/`, the **first** model call took 7, 67, 135, 152 and 223 seconds, and 61–80 per cent of everything the model writes is thinking nobody could see. So the live call is streamed and the strip gains at most two more lines, each of them somebody else's words: the search the model just ran and one thing it returned, and the model's own summarised thinking, labelled as its own. They arrive at most about one a second per call — the newest wins, nothing queues — they sit **outside** the polite live region because they change every few seconds and must not be announced, and nothing about them moves: a line of text replaced by another line of text is a reading, not a motion, which is the rule record 0023 wrote down. **A replay shows none**, and nothing on screen says so.

**What it costs.** Engine timings are measured in `spec/multiverse/propagation.md`, which owns them: the Hormuz strike branch — the stored example's seven claims plus the one the strike inserts — takes **67 milliseconds** over a sixty-one-day window. What a *generation* costs in money and minutes is measured in [`docs/measurements.md`](docs/measurements.md), dated run by run.

One proposal per call is deliberate: each is small enough to validate, stream, and retry, and the pipeline — not the model — composes them into a map. This is the constitution's *minimal output principle* applied.

## 4. Data model at a glance `[built]`

Defined once as frozen pydantic models in `domain/`; the same models serve as the model's output schema, the API's response shapes, and the source of the frontend's types (`frontend/src/api/schema.ts`, generated by `scripts/gen-types.sh` and committed). Full definitions live in `spec/graph/` and `spec/multiverse/`; the vocabulary is in `spec/vocabulary.md`.

Every row below exists as code; four carry a `[planned]` clause naming a change that is decided and accepted but not yet written. The last column names the thing that actually enforces the rule — a function in `domain/validity.py`, a validator that runs when the object is built, or the test that would fail.

| Type | What it is | Key rule, and what enforces it |
|------|-----------|----------|
| `Proposition` | A claim checkable by a date, judged by a named source. Kinds: `hypothesis`, `event`, `market` (names a contract to take a side of, or an instrument that moves), `not_tradeable` (names the reason) | Criteria, judge and resolve-by required (INV-1): `_claims_say_how_they_are_judged`, `test_validate_rejects_unresolvable_proposition`. A `market` claim names a payoff — `ContractPayoff` or `PricePayoff`, told apart by a **required** `kind` that neither shape defaults, so the model cannot leave out the one field that says which it meant, and neither naming a price — and a `not_tradeable` one a reason (INV-9): `test_validate_requires_payoff_on_market`, `test_validate_requires_reason_on_not_tradeable`, `test_both_payoff_shapes_require_their_kind`. Identity of the trade — venue, contract, instrument — lives in `domain/`; its price lives in `grounding/` (ADR-0013). **`[planned]`** (decision record 0017, stack 05): the in-between kind is renamed `event` → `step`, and every claim gains a required `persistence` saying which kind of truth it is — an **event**, which happens once and stays happened, or a **state**, which holds over a stretch of time and can stop. A claim without it is refused by name; no default is applied |
| `Link` | A causal claim from one proposition to another: mechanism, strength (log-odds), lag, signal shape, `trigger` (one-time shove) or `sustain` (continuous hold), provenance, `reflexive`. It carries no self-reported confidence: the rationale is the argument, provenance is the receipt | Rationale required, and a provenance claiming evidence cites a source (INV-2): `_arrows_say_why` and `_arrows_claiming_evidence_cite_it`, `test_validate_rejects_link_without_rationale`, `test_validate_rejects_unsourced_documented_link`. **`[planned]`** (decision record 0017, stack 05): a `sustain` arrow may leave only a claim that can stop holding — a state — and an arrow leaving anything else is refused by name. The sign of an arrow's number decides which of a state's two rates it bends, so the arrow itself gains no field |
| `Belief`, `Beliefs` | A likelihood with a range and an owner — model, user, market — in three named slots, never a dictionary | `0 ≤ lo ≤ p ≤ hi ≤ 1` refused at construction and re-checked over a whole map (INV-7): `_likelihoods_sit_inside_their_own_range`. Never averaged across owners (INV-11): `test_beliefs_never_merged`, which reads our own source code rather than trusting good intentions |
| `Graph` | Propositions + links + which claim started it. Immutable | Exactly one hypothesis, at least one terminal, and no loops once reflexive links are set aside — each of which needs a delay (INV-6, INV-9): `_exactly_one_starting_claim`, `_map_ends_somewhere_actionable`, `_no_loops_once_feedback_is_set_aside`, `_feedback_arrows_take_time`. Frozen: `test_models_are_frozen` |
| `Intervention` | Six frozen types — `do`, `observe`, `insert`, `retune`, `refine`, `believe` — told apart by a `kind` field, which is what makes the generated TypeScript a tagged union. **Applying one is built**: `apply` in `domain/patch.py` folds a branch's edits onto a map in order and returns the map they left behind plus every value they fixed | `believe` refuses any belief but the user's own, at construction: `test_believe_requires_user_owner`. The union discriminates on `kind`: `test_intervention_discriminator`. **There are twenty violation codes now: fifteen faults in a map and five refusals.** The fifteen are what `validate` finds — the last added on 2026-09-21, `duplicate_link`, a second arrow between one **ordered** pair of claims, which propagation would add to the first so that two arrows push twice as hard as either claims (decision record 0003, second amendment; both directions of a pair stay legal, because that is what a feedback arrow is); and two on 2026-09-17, a half-life on a push that holds and a spike that never says how fast it fades, which are one idea checked both ways: a shape and the numbers describing it must agree. `test_validate_rejects_half_life_without_impulse` and `test_validate_rejects_impulse_without_half_life` guard them. Four of the five refusals are what folding a branch onto a map finds in an *edit*: `unknown_target`, `unknown_link`, `duplicate_id` and `edit_not_applicable`. The fifth, `worlds_not_comparable`, is the one that is not about an edit at all — two worlds built from different maps, seeds or loop sizes are refused rather than compared, because subtracting one from the other would leave noise rather than the change somebody made. No map can carry any of the five. They are local invariants of the graph and multiverse chapters rather than any of the fifteen, and every one of them is decided by our own code and reported as a plain sentence a person can act on.

Three rules the engine rests on have named tests of their own, each written because a plausible wrong implementation passes everything else and fails exactly one of them. `test_band_is_not_sampling_noise` freezes every prior at a point **and holds every arrow's push at exactly what the map states** — both, since the spread landed, because with only the priors frozen there is still something genuinely uncertain on the map — and demands a range of no width; an engine reporting how much its own sampling wobbled would fail only here. `test_range_matches_analytic_first_order_on_fixture` checks the sampled range against a second, independent method that now carries a term per arrow as well as a term per prior. `test_shifted_needs_agreement` measures two ranges that overlap across more than half their width while every version of the map moves the same way, which is why a change is read off the paired difference and never off whether two ranges overlap.

Three more were written for the spread itself: `test_a_documented_arrow_gives_a_narrower_band_than_an_asserted_one` (the table means what it says), `test_link_spread_comes_only_from_provenance` (nothing else may widen an arrow), and `test_adding_an_arrow_does_not_move_another_arrows_draws` (each arrow's draws are keyed by its own identifier, so a map that grows does not quietly re-roll the map it grew from).

## 6. Runtime `[built]`

Everything below runs today except stored state, which is marked `[planned]` in its own bullet and has no code, no database file and no volume behind it.

- **Development.** `make dev` (which is `docker compose up --watch` under a trap) runs both halves with reload, prints the app's address and the address of the server's own interactive documentation before it starts, and on Ctrl+C stops both halves and removes their containers. The browser app answers on <http://localhost:5173> and the Python server on <http://localhost:8000>. Edited files under `backend/src` and `frontend/src` are copied into the running containers, which reload themselves; a change to a file that says *which packages are installed* — `backend/pyproject.toml`, `backend/uv.lock`, `frontend/package.json`, `frontend/package-lock.json` — rebuilds the image instead, because copying a file cannot install a package. The browser app does not start until the server answers its health check.
- **Production-like.** `docker compose -f compose.yaml -f compose.prod.yaml up --build` (or `make prod`), on <http://localhost:8080>. Two multi-stage images. The server is a `python:3.12-slim` image holding only the built virtual environment — no package installer, no lock file, no source tree — run as a user that is not root. The browser app is a folder of built files served by `nginx:alpine`, and that same web server forwards anything beginning with `/api` to the Python server, so the whole app is one origin. The server is not published on the host at all: only the web server can reach it.
- **Versions.** Python 3.12 (`backend/.python-version`, `python:3.12-slim`), packages installed by `uv` 0.12 taken from the image its authors publish, Node 24 (a long-term-support release). The same versions are pinned in the Dockerfiles and in the checks, so a laptop's newer Node cannot make a pull request pass that a deployment would fail.
- **Packages the server needs to run**, eight of them: the web framework and the server that runs it, the data-shape library and its settings companion, a graph library for the loop check, `numpy` for the arithmetic of both engines, a library that mints sortable identifiers, and — **new with stack 04** — **the model vendor's own client library**, used in exactly one file, `engine/client.py`, which is the only place in this program that talks over the network to a model. Decision record 0006 chose the vendor's library over a framework that would hide the calls a reader wants to see. The browser app adds no runtime dependency for any of this.
- **Streaming through the packaged proxy.** Left to itself the static-file server would collect a whole answer before passing it on, which would turn a map growing over ten minutes into a spinner and then a dump — and would do it only in the packaged image, where nobody develops. So `docker/nginx.conf` turns buffering and caching off for `/api/`, allows chunked answers, and raises the read timeout to an hour, because that timeout is measured between two pieces of one answer and a model can think for a minute. The answer carries the matching header itself. Both are pinned by tests: `test_the_packaged_proxy_is_told_not_to_collect_the_body` and `test_the_answer_carries_the_header_a_proxy_reads`.
- **State.** `[planned]` **No database at all** (decision record 0021, 2026-09-21, replacing the single SQLite file this bullet used to plan for). A finished generation is served back by its id from the line-by-line file a kept run already writes — the same format a recording uses, one loader for both. No database service, no accounts, no multi-tenancy in v1. Nothing is stored yet — the app keeps nothing between requests, and no volume is declared in either compose file.
- **Configuration.** The real `.env` is git-ignored, and `docker compose` reads it from the top of the repository on its own. Values are read once in `settings.py`, whose field names *are* the variable names, so there is no mapping to learn. Both keys (`ANTHROPIC_API_KEY`, `FRED_API_KEY`) are optional: the app starts, the first screen loads, and every test passes without either. Four settings shape a run — **which model** (`claude-sonnet-5` unless told otherwise, with `claude-opus-5` one setting away), **how hard it tries**, **where recordings are read from**, and **where a paid run is written**. Effort has **two pinned defaults** behind that one setting (Kent, G13, 2026-09-21): the recorder sends nothing and takes the service's own — *record rich*, because a recording is made once and played back by everybody — while a live run through the stream route asks for **`medium`**, because somebody watching a map arrive is waiting. Measured on one Hormuz map each: 27 seconds a call against 79. **The scorecard, `make eval`, asks for `medium` too** (Kent, 2026-09-21, later the same day) — it is run while a prompt is being worked on, and at the recorder's effort one case took the best part of an hour — so the rule is one rule: **only the recorder sends nothing.** `make eval EFFORT=as-recorded` reaches the recorder's effort by name. The receipt and a recording's header say which effort made the map. The model and the effort are pinned for a whole run and never varied between its calls, because changing either mid-run would throw away the remembered prefix the run reads back at a tenth of the price. A fifth setting shapes a *viewing* rather than a run: **`KATALYST_REPLAY_PACE`**, how long a replay waits between two of its events, in seconds — `0.6` is the speed a person watches a map arrive at and `0` means no pause at all. It is one number rather than a length with a switch beside it (2026-09-21), and it is never a field on a request, because a client that could skip the pacing could skip the thing a recording exists to show.
- **Health.** `/api/healthz` (the process is up; depends on nothing) and `/api/readyz`, which answers the only question that matters to a first screen: **can this copy build a map at all?** It reports whether a model key is configured — never the key — **and which recorded generations can be replayed**, each with the day it was recorded. It reads *ready* when either is true, so a reviewer with no key is told plainly what works rather than being shown a dead button. Every browser-facing route lives under `/api/`, so the static-file server forwards one prefix. The container health check calls `/api/healthz` using Python's own `urllib`, because the small images carry neither `curl` nor `wget`.

`make test` ran **642 server tests and 358 browser tests** on 2026-09-21 — dated, because the figures move with every round — and `npm run e2e` in `frontend/` (Playwright, the tool that drives a real browser) runs **14** end-to-end tests. None of them needs a key and none of them reaches the network: the end-to-end tests start both halves themselves, and every model answer in the suite comes off disk. `make eval` is the one thing in this section that is not in `make test` and never will be.

**Nothing in either suite is skipped any more.** `frontend/src/graph/__tests__/diffState.test.ts` › "agrees with the server's own affected set" was skipped while there was nothing to compare against; the canvas asks the engine now, so it runs. It was kept rather than deleted because the day the browser and the engine disagree about what an edit reached is the day this product stops being traceable, and that is the test that catches it.

Coverage is measured on the rules layer alone — `backend/src/katalyst/domain/` — and stands at 100% of lines and branches; no other layer has a coverage threshold, on purpose (decision record 0008).

The one test that matters most is still `backend/tests/unit/test_import_boundary.py`. `test_domain_imports_nothing_impure` reads every file under `domain/` — seventeen of them now, the five newest being the by-deadline core — and fails if any imports the engine, the routes, the grounding layer, or a model client. It is the rule "the model proposes; our code decides" made mechanical.

**Runs on every pull request**, in six checks named `backend`, `frontend`, `types-fresh`, `docker`, `e2e` and `recordings` (`.github/workflows/ci.yml`). None of them is given an API key, and none needs one. `types-fresh` regenerates `frontend/src/api/schema.ts` from the server's own description of itself and fails if the result differs from what is committed, which is what stops the two halves drifting apart. `backend` does the same thing for `docs/worked-numbers.txt` in a step of its own rather than in a seventh job, because it needs nothing the Python half has not already installed. `e2e` installs Chromium alone and starts both halves. **`recordings`, new with stack 04, reads every committed recording**: that each parses, that each starts and ends where a generation does, that none stores likelihoods it should recompute, that no two were made from the same sentence, and that each was made against the words this program uses now — a prompt hash the build compares. It passes on an empty folder too, so it was green from the commit that added it.


**One generated file owns every number the worked example quotes** `[built]`. `make numbers` runs the shipped engine on the Strait of Hormuz map at the example's own seed and the shipped loop sizes and writes [`docs/worked-numbers.txt`](docs/worked-numbers.txt): each claim's reading in each world, what the strike branch and the two observations did to it, the ranked list of endings each edit reached, the sentence beside each list, the number on every arrow, and where each band comes from — with the numbers a person typed into the fixture kept in a part of their own, labelled apart, because those are stable and the computed ones all move together. Every line starts with a stable name such as `B · base · reading`, so prose cites a line rather than restating a figure. The file is committed; the `backend` check runs `make numbers-check` and fails when a number has moved, and `backend/tests/unit/engine/test_worked_numbers_as_a_program.py` starts the program in its own process so a developer finds out locally in two seconds instead of on a pull request. Three tests are the whole contract: a last bit of disagreement between machines is forgiven, a real move is caught and its line named, and a word that changed is caught. Computed numbers print twice, as the product prints them and at five decimal places — a choice about **reading**, since the screen never shows more than two significant figures and the rules layer will not call a claim *shifted* until it has moved by 0.005. **What makes the file reproducible is the check, not the digit count.** `make numbers-check` works every number out again and compares numbers *as numbers*, within a tolerance of 2e-05, while comparing every word, date and state character for character; the as-printed column is not compared as text, because a number two machines agree about to eight decimal places can still round two ways and neither is wrong. An earlier version compared the file byte for byte and went red on the build machine over exactly that, which is how this was found. Measured on 2026-09-21: one step of the float32 grid the engine samples on is 5.96e-08, perturbing numpy's exponential by one step moves no number here further, nothing amplifies, and Linux and macOS produced byte-identical files — and the check does not depend on that last fact staying true. The rule this buys: **a number the engine computes appears in a document only where that file is one link away.** It matters most at the next engine change, when every number moves at once and the diff of one file is the whole reviewable statement of what moved.

**How much of the browser suite a change has to run** `[built]`. Three tiers, written down in decision record 0008's dated amendment of 2026-09-21 — which is also where the evidence for them is, because until that day the standing bar was twenty cold runs and it was recorded nowhere at all. **Tier 1**, every pull request that touches the browser: one cold run of the end-to-end tests here and the build, which is a second, slower machine on purpose. **Tier 2**, a change to anything whose correctness is about timing — the canvas, the layout, the stream, the growing map, keyboard focus: tier 1 and a test with no browser that injects the bad timing deliberately, as `frontend/src/graph/__tests__/onTheGlass.test.ts` does for a late layout answer and `frontend/src/graph/__tests__/ports.test.tsx` for a dropped size notification. **Tier 3**, a repeat bar: only for a rare failure somebody has actually seen, on that one test rather than the suite, and sized to the failure's own rate.

Deliberately skipped in v1: snapshot tests of rendered graphs, load tests, coverage thresholds outside `domain/`, and any check on a model's wording. A lint that scans prose for decimals is not here either: the numbers file and the build check are the gentle version of that rule, chosen on 2026-09-21 over a strict one that would have deleted the passages that teach.

**Two things the browser half checks that no test can.** Whether the interface looks like somebody else's component library, and whether a greyscale screenshot still says everything the colour one did, are checked by a person against the thirteen-line visual review checklist in `spec/workbench/README.md`. A checklist line is a checkable thing; it is checked by eye, on every screenshot, before any of it is shown to anyone.

## 10. Not yet built, and known unknowns

Stacks 00, 01 and 02 are merged, **both halves of stack 03 are built**, and **stack 04 is complete**.

**03a — the engine.** `apply` folds a branch's edits onto a map and hands back the map they left behind plus every value they fixed; `propagate` works every likelihood through time into a `World`; `diff` says what moved between two worlds and ranks the endings that did; `sensitivity` flips each claim in turn and records what each flip would move; and three routes serve them — `POST /api/worlds`, `POST /api/worlds/diff`, `POST /api/worlds/conditional`.

**03b — the canvas.** The stored example draws: tiles with typed sockets, belief chips, wires carrying the shape, strength, delay and provenance of each push, automatic left-to-right layout on a background thread, a hover lens, a persistent Inspector, a path bar, two worlds in one set of coordinates with a delta rail and a branch panel beside them, the six edits as six buttons, the whole thing worked from the keyboard, and the same world as a nested list for a reader who never sees the picture.

**Stack 04 joined the canvas to the engine, taught the server to write a map, and taught the browser to watch one being written.** `App.tsx` hands the canvas an `ApiWorldSource`, with the stored example kept as a fallback that says on screen when it is being used. `engine/` calls the model one proposal at a time, decides every provenance from what the search returned, prices the run, streams eight kinds of event, keeps a transcript in memory, writes a recording and plays one back. The canvas folds those eight events into a map as they arrive. `evals/` scores four example hypotheses on structure. And every version of the map now draws each arrow's push as wide as that arrow's receipt says it should be.

**The first screen is built** `[built]`, and it is one screen rather than two. It offers four ways to start — the stored map, the committed recording badged *replay*, a live run of one of the four example sentences, and a sentence of the reader's own — always the same four, in the same order, in the same words, whether or not a model key is configured. What changes is only what is enabled and the reason printed beside what is not: the key is read as a reason on a disabled control and never as a decision about what to draw, which is what lets a reviewer holding a key still reach the recording. Each press names how the run starts, and `App.tsx` passes that through untouched. What a live run costs and how long it takes is on screen **before** the press, read off the recorded run's own receipt as `GET /api/readyz` carries it, printed with the day it was measured, and absent with a reason where no recording carries a receipt this engine can read. - **Grounding, half built.** `grounding/` now reads a prediction market's own saved answers and works a price out of them — `quote.py`, `recorded.py`, and the one opt-in live read in `polymarket.py` — and one committed dated file holds a real contract: **recorded first, fetched second, and a venue's number a point rather than a range** (decision record 0020). `[planned]` Still ahead: `fred.py`, the economic-data adapter, so a price ending has a measured level to start from — that level is an **observation** and never fills the `market` belief — and the fixture's own market likelihoods, which are still numbers a person wrote down by hand with the source beside them. **Kalshi is cut from version one.** Stack 06.
- **The thesis, its pure half built.** Eight files, from a price to the document a reader leaves with. The **edge**, in `thesis/edge.py`: a claim's model number, read from the world with nothing fixed by an edit, against the offer to buy and the bid to sell, less the fee — or a named refusal and the break-even (decision record 0018). A card request therefore carries **two** worlds, the base world and the world on screen, because the edge is read from the first. **`thesis/draws.py` is the one contract with the engine**: for each drawn world, the day each claim came on, the day it went off, and how much that world counts. Nothing else crosses, and **`domain/` gained nothing**. On that sample, `paths.py`, `position.py`, `lift.py` and `ceiling.py` work out the price path, how often each end of the reader's own exit is reached first, *what takes you out*, and the greyed ceiling; `card.py` arranges the nine sections and `export.py` writes the document and the page. **No stop is derived** (decision record 0019, which reverses the requirement that one be): the stop, the target and the horizon are typed. `[planned]` Four things are still ahead. The adapter that turns the engine's own sample of worlds into `Draws` — so no card has yet been built over the recorded map, and every set of drawn worlds in the tests is written down in the test that reads it. The one-at-a-time sweep gains one change — **each claim flipped both ways**, because which direction hurts depends on which side of the trade the reader is on — which is about fifteen lines in `domain/diff.py` and lands **after** stack 05 has finished rewriting that file; the two filters behind *what to watch* sit on top of it. Five routes: `POST /api/thesis/quote`, `…/quote/refresh`, `…/position`, `…/card`, and `GET /api/thesis/export`. And the dock that draws a card. Stack 06.
- **Probes and refinement.** `refine` — splitting a claim into finer claims — and probes and their value-of-information ranking are **not built in version one** (decision record 0021); folding a branch refuses `refine` today with a sentence saying so, which is how INV-10 is met. Still open and unscheduled: the propagation of reflexive links, a market feeding back on the world it is measuring, which the engine sets aside rather than working through. The engine already works out `range_shares` — how much of each claim's range comes from not being sure of each prior — and it travels on every world the three routes serve, but nothing on screen reads it.
- **Storage.** Nothing is kept between requests: no database file, no volume in either compose file, no session. **And no database is planned**: a finished generation will be served back by its id from the line-by-line file a kept run already writes (FR-31, decision record 0021).

**What a generation costs** is measured, dated and kept in [`docs/measurements.md`](docs/measurements.md) — the run, the model, the settings, the money, the minutes, and where the raw record is. It is added to and never rewritten, and nothing in this file restates a figure from it.

- **Replay mode** (asked 2026-09-17, settled 2026-09-17, **built in stack 04**; **who chooses it amended 2026-09-21**). An example plays from a committed generation transcript through the live event stream. Decision record 0012 answered it and was accepted the same day. **The key used to decide** — with one configured every card ran live and the committed recording was unreachable, with none the only free path ran — which left the reader no say in either direction. The request now names its own start, so a recording asked for plays whether or not a key is present, and a live run asked for with no key is refused in one sentence rather than quietly replaced. What shipped: a recording is the stream itself, one JSON object per line, with a header carrying the map's identifier, the seed, the day and a hash of the prompt it was recorded against. Two events are not replayed as they were recorded — the receipt is **rebuilt** with no money in it and the word *replay* on it, and the likelihoods are **recomputed** from the seed by `domain/`, so a recording stores none and replay and live agree by construction. **One recording is committed**, the Strait of Hormuz; the other three example sentences are recorded by `make record-demo ONLY=<example>` when the owner chooses to pay for them.

- **Propagation engine** (asked 2026-09-16, settled 2026-09-17, **built in stack 03a**). The question was whether to ship a single deterministic sweep first and add sampling later. Decision record 0014 answered it: the engine is **two nested loops** — two thousand versions of the map, eight worlds under each — because there are two kinds of not-knowing and they must be kept apart. How the dice fall is already inside the likelihood; how sure we are of the numbers put in is the range around it. A single deterministic sweep cannot say the second thing at all, so it was never an option. What shipped is exactly that: sixteen thousand worlds, the likelihood kept rather than the coin flip, and the spread of the eight worlds inside a version subtracted back out so the range is not a report on our own sampling. **The timings and the memory are measured in `spec/multiverse/propagation.md`, which owns them, and are not restated here** — a figure kept in two places is a figure that goes stale in one of them, and this one already had. The shape of the answer: the Hormuz strike branch over a sixty-one-day window is well under a tenth of a second; a sixty-claim map over the same window is under a second; a year-long window capped at 180 points is a second or two. The cost is claims times days worked out times worlds, and the window is the term that grows.

- **How wide an arrow's push is** (settled by decision record 0014 on 2026-09-17, deferred, **built in stack 04b**). The record decided that an arrow's spread should be read off its provenance and held the work back, because every arrow on the stored example was written by hand and widening them all equally would have taught nobody anything. Generation now produces arrows that genuinely differ, so it landed: seven words, three widths — narrow for the three that mean somebody fetched something, wider for a stated mechanism or a person's own judgement, widest for a bare assertion — applied on the same log-odds scale the push itself is written in, from a stream of random numbers keyed by each arrow's own identifier so that adding an arrow cannot shift what another one drew. **The width is derived from that word every time and never stored**: there is no `strength_lo` and no `strength_hi`, now or ever.
